# 网游数值战斗写作

用可核对的数值变化推动原创战斗剧情。人物的目标、怪物的威胁、战术选择和代价始终比连续刷面板更重要。仅在当前作品确实是游戏题材，或用户明确要求网游战斗时使用。

## 第一优先级：数值必须有来源

- 先确认本章目标、大纲、人物卡、世界规则和已有正文。启用游戏数值档案时，以账本给出的本章起始状态、已记录变化和已确认目录为准；需要核对具体人物、装备或技能时调用 `read_game_state`。
- 怪物若已有独立人物卡和数值档案，按同样方式读取并追踪它的等级、生命、魔法、属性、装备与技能。怪物只有文字设定时，可以写攻击范围、动作规律、破绽与受伤表现，不得擅自给它编造精确生命、攻击、防御、掉落或经验值。
- 严格区分面板属性与战斗判定。账本可计算生命、魔法、攻击、速度、闪避等面板值；战斗公式、概率上限与速度对应行动频率由作者在规则版本中配置，默认不启用。先读取本章生效规则；只有作者已启用规则且明确提供判定点数、双方档案与倍率时，才可按该规则核对结果。不得虚构随机点数。不得把“攻击 60、怪物防御 20”擅自算成“造成 40 点伤害”，也不得把闪避面板 80% 写成必然闪避 80% 攻击。
- 仅在作者指令、大纲或已确认规则确定了具体结果时，写精确扣血、耗蓝、升级、加点或掉落。若本章确实需要记录变化，先核对人物与目录 ID，再用 `stage_game_change` 暂存，并以工具返回的前后值继续写；工具不可用时不要声称已记账。一次剧情变化只暂存一次，未经作者确认不称为定稿。

## 拆书参考只借写法

用户指定或项目已选网游拆书时，先按标题或 ID 定位对应作品，优先读取 `read_project_data(entity_type="available_deconstructions", summary_only=true)` 的目标条目；需要细节时再读取这一本的分析。只提炼战斗节奏、敌方机制揭示顺序、面板数字出现的时机、信息差和胜负转折。没有指定参考或资料不足时，直接按本作品规则创作，不要声称借鉴了未读取的作品。

若拆书库中有对应作品，可择一借鉴高层节奏：《重生之贼行天下》的分析强调“先明确风险与资源，再压缩重复攻防、放大临界血量与结算”；《网游之近战法师》的分析强调“指令或出招→执行→反馈”的短循环，每轮让规则认知发生一点变化。采用哪一种取决于用户指定的主参考和本章战斗目标，不把两部作品的具体内容混合。

参考作品的人物、怪物、技能名、场景、数值、招式组合、掉落物、情节顺序和原句都不能移植到本作品。不要把多本拆书内容拼接成一场战斗。

## 战斗推进

1. **开场对照**：交代双方位置、目标、可见威胁与已确认的关键数值；只报会改变判断的两三项，不抄整张属性表。
2. **试探与反馈**：一次动作对应一次反应和后果。先写招式的目标、距离、耗费或冷却，再写怪物如何应对，以及人物从中确认了什么规则。
3. **机制与取舍**：怪物的攻击规律或弱点必须先有可观察线索。人物依据剩余生命、魔法、装备和技能条件改变站位、节奏或目标；不要靠未登记的技能、临时加点或突然出现的装备脱困。
4. **关键转折**：只在明显变化处插入简短数字对照，例如“生命 86→53”“魔法 42→18”；数值与伤势、动作受限、队友反应互相印证。没有确认的伤害量时只写可见后果，不伪造数字。
5. **结算与余波**：战后核对生命、魔法、消耗品、装备、经验、等级与掉落；只呈现已确认或已暂存的变化。让战斗代价影响下一场景，而非打一页后状态自动复原。

## 交付前检查

- 同一时点的双方属性、生命与资源是否前后一致？本章变化发生前后有没有混用数值？
- 每次命中、闪避、破防和胜负是否有已确认规则或可见动作支撑？怪物是否真正反击、改变策略？
- 数字是否服务决策，而不是把正文写成逐回合日志？参考资料是否只贡献方法，没有带入可识别内容？
- 用户要求正文时只交付正文；要求大纲或审查时再说明数值依据与尚未建立的规则。
